# 要件定義書 — CornerCast(仮称)

**プロジェクター1台・3面没入空間のためのiPadプロジェクションマッピングアプリ**

| 項目 | 内容 |
|---|---|
| ドキュメント版数 | v1.0(初版ドラフト) |
| 作成日 | 2026-07-18 |
| 対象プラットフォーム | iPadOS 17以降 |
| 開発言語/FW | Swift / SwiftUI / Core Image / Metal / AVFoundation |
| ステータス | レビュー待ち(§10の未決事項に回答が必要) |

---

## 1. 背景と目的

### 1.1 背景
部屋の「左壁・正面壁・床」の3面が交わるコーナーに、プロジェクター1台で斜め上方から映像を投影し、家庭内に「SFコックピット風」の没入空間を作りたい。既存のプロ向けマッピングソフト(MadMapper等のPC製品)は重厚で高価であり、家庭でのカジュアルな用途には過剰。モバイル向けの既存アプリ(DynaMapper等)は汎用的な「面の追加」はできるが、**「部屋のコーナー3面をワンセットで扱う」という体験に最適化されたものは存在しない**。

### 1.2 目的
- AI生成等で用意した1本の超広角動画を、iPad単体でリアルタイムに「3分割 → 射影変換 → 再合成」し、プロジェクターへ出力する。
- タッチ操作だけで、実際の部屋の角に映像を「カチッと」フィットさせられる直感的なキャリブレーションUIを提供する。
- 重厚なPCソフトなしで、セットアップから投影まで10分以内に完了できる体験を実現する。

### 1.3 ゴール指標(v1)
| 指標 | 目標値 |
|---|---|
| 初回セットアップ〜投影開始 | 10分以内 |
| キャリブレーション操作の反映遅延 | 100ms以内(体感で「リアルタイム」) |
| 投影フレームレート | 30fps以上(60fps目標)、4K/H.265ソース時 |
| 連続投影時間 | 2時間以上(熱・バッテリー条件は§7参照) |

## 2. ユーザーと利用シナリオ

### 2.1 想定ユーザー
- **プライマリ**: 自宅に趣味の没入空間を作りたいガジェット/映像好きの個人。プロジェクターとiPadを所有。映像編集やプログラミングの専門知識は不要とする。
- **セカンダリ**: 小規模イベント・店舗ディスプレイ・子供部屋演出などで簡易マッピングをしたい人。

### 2.2 コアシナリオ(ハッピーパス)
1. プロジェクターを部屋の右後方・天井付近に設置し、コーナー(左壁×正面壁×床)へ斜めに投影する。
2. iPadをUSB-C – HDMIアダプタでプロジェクターに接続する。
3. アプリを起動すると、プロジェクター側に**テストパターン(面ごとに色分けされたグリッド)**が全画面表示される。
4. iPad画面上の3つのメッシュ(左壁/正面壁/床)の4隅ポイント(計12個)をドラッグし、テストパターンの各グリッドが実際の部屋の面にぴったり合うよう調整する。
5. 調整結果を「プリセット」として保存する(次回以降は再調整不要)。
6. 写真ライブラリ/ファイルから超広角動画を読み込むと、動画が3分割・射影変換・合成されてプロジェクターから投影され、部屋のコーナーが立体的な映像空間になる。

### 2.3 ユーザーストーリー(抜粋)
- 「映像の知識がない私でも、ツマミをドラッグするだけで壁の角に映像を合わせたい」
- 「一度合わせた設定は保存して、次回は電源を入れるだけで使いたい」
- 「投影中はプロジェクター側にボタンやUIが一切映ってほしくない」
- 「調整の最後の1〜2pxを指ドラッグでは合わせきれないので、微調整手段が欲しい」

## 3. スコープ定義

### 3.1 スコープ内(v1)
- 動画1本(ローカルファイル)を入力とした3面マッピングと外部ディスプレイ出力
- 静止画の入力(動画の前段階として。テスト・調整用途にも有用)
- 3メッシュ×4点のパースペクティブ補正、クロップ領域調整、プリセット保存

### 3.2 スコープ外(v1では作らない)
- 複数プロジェクター、エッジブレンディング
- ストリーミング入力(NDI/Syphon/AirPlay受信)、カメラ入力
- 4点を超える多点メッシュワープ(ベジェ/グリッドワープ)
- コンテンツ制作機能(動画生成・編集はアプリ外で行う)
- Android / Apple TV / Mac 対応

### 3.3 将来構想(v2以降。設計上は拡張を妨げないこと)
- ジャイロ連動視差(iPadの傾きで視界が動くコックピット演出)
- 面ごとの音響パンニング(左壁→左ch、正面→センター等)
- LiDAR搭載iPad Proによるコーナー自動検出・半自動キャリブレーション
- プレイリスト/シーン切替、外部MIDI/OSC制御

## 4. 機能要件

優先度は MoSCoW(M=Must/S=Should/C=Could)で表記。IDは実装・テストのトレーサビリティ用。

### 4.1 外部ディスプレイ出力

| ID | 優先度 | 要件 |
|---|---|---|
| F-OUT-1 | M | 有線接続(USB-C – HDMI)された外部ディスプレイを検出し、**ミラーリングではなく独立したコンテンツ**を全画面表示する(`UIWindowScene` の外部ディスプレイ用シーンロールを使用)。 |
| F-OUT-2 | M | 外部ディスプレイには合成済み映像のみを表示し、UI要素・ステータス・カーソル等を一切表示しない。 |
| F-OUT-3 | M | 接続/切断をアプリ実行中に検出し、自動で出力を開始/停止する。iPad側UIに接続状態(解像度・リフレッシュレート含む)を表示する。 |
| F-OUT-4 | M | 外部ディスプレイ未接続時は、iPad画面内のプレビュー領域に出力相当の映像を表示する(自宅外での事前調整・開発用)。 |
| F-OUT-5 | S | 出力解像度は接続先ネイティブ解像度に追従する(1080p/4K)。レンダリング解像度を出力解像度に合わせる。 |
| F-OUT-6 | C | AirPlay経由の出力(遅延が大きい旨の警告を表示した上で許可)。 |

### 4.2 コンテンツ入力

| ID | 優先度 | 要件 |
|---|---|---|
| F-SRC-1 | M | 「ファイル」(Files/iCloud Drive)およびフォトライブラリから動画(H.264/H.265、最大4K/60p)を読み込める。 |
| F-SRC-2 | M | 静止画(JPEG/PNG/HEIC)も同一パイプラインで投影できる。 |
| F-SRC-3 | M | 動画のループ再生(シームレスループ。終端で黒フレームを挟まない)。 |
| F-SRC-4 | S | 再生/一時停止/シーク/音量のトランスポート操作。 |
| F-SRC-5 | S | コンテンツ制作用の「クロップガイドテンプレート」(3面の切り出し領域を示すPNG)を書き出せる。ユーザーはこれをAI生成や動画編集時の下絵として使う。 |
| F-SRC-6 | C | 複数コンテンツの登録と切替(簡易プレイリスト)。 |

### 4.3 3分割(クロップ)

| ID | 優先度 | 要件 |
|---|---|---|
| F-CROP-1 | M | 1フレームを「左壁用/正面壁用/床用」の3矩形領域に切り分ける。初期値は左1/3・中央1/3・下段等のプリセット配置。 |
| F-CROP-2 | S | 各クロップ矩形の位置・サイズをUIで編集できる(ソース映像のサムネイル上で矩形をドラッグ)。 |
| F-CROP-3 | S | クロップ領域の重複を許可する(面の境界を少し重ねてコーナーの連続感を出す用途)。 |

### 4.4 射影変換(4点補正)

| ID | 優先度 | 要件 |
|---|---|---|
| F-WARP-1 | M | 3面それぞれに独立した4点(計12点)のパースペクティブ変換(ホモグラフィ)を適用する。 |
| F-WARP-2 | M | iPad側UIのコントロールポイント操作が、投影映像へ100ms以内に反映される。 |
| F-WARP-3 | M | 変換後の3映像を1枚のキャンバス(出力解像度)に合成する。面が重なる場合の描画順は「床 → 左壁 → 正面壁」を既定とし、背景は黒。 |
| F-WARP-4 | M | 凹型(自己交差)の四角形など不正な形状になった場合も、クラッシュ・フリーズせず描画を継続する(結果が乱れるのは許容)。 |
| F-WARP-5 | S | **頂点リンク**: 左壁の右辺2点と正面壁の左辺2点(部屋のコーナーで一致すべき点)、正面壁の下辺と床の上辺を「リンク」し、片方を動かすともう片方が追従するモードを提供する。継ぎ目のズレを構造的に防ぐ。 |
| F-WARP-6 | S | 面ごとの明るさ・ガンマ補正(床は投射角が浅く暗くなりやすいため)。 |
| F-WARP-7 | C | 面ごとのエッジフェザリング(境界を数pxぼかして継ぎ目を目立たなくする)。 |

### 4.5 キャリブレーションUI(iPad側)

| ID | 優先度 | 要件 |
|---|---|---|
| F-UI-1 | M | 3つのメッシュ(左壁/正面壁/床)と各4隅のコントロールポイントを表示し、指でドラッグできる。ポイントのタッチ判定は視覚サイズより大きく(44pt以上)取る。 |
| F-UI-2 | M | テストパターンモード: 面ごとに色分け(例: 左=シアン/正面=マゼンタ/床=イエロー)されたグリッド+面ラベルを投影する。調整はこのモードで行うことを想定。 |
| F-UI-3 | M | 選択中ポイントの微調整UI(十字キーで±1px、長押しでリピート)。 |
| F-UI-4 | M | 全リセット/面単位リセット。誤操作に備えたアンドゥ(直近20操作)。 |
| F-UI-5 | S | ポイント座標の数値表示・直接入力。 |
| F-UI-6 | S | 編集ロック(調整完了後、誤タッチで動かないようにする)。 |
| F-UI-7 | C | 2本指ドラッグで面全体を平行移動、ピンチで面全体を拡縮。 |

### 4.6 プリセット(永続化)

| ID | 優先度 | 要件 |
|---|---|---|
| F-PRESET-1 | M | 12点の座標・クロップ領域・明るさ設定等を名前付きプリセットとして保存/読込/削除できる。 |
| F-PRESET-2 | M | 最後に使用した状態を自動保存し、次回起動時に復元する。 |
| F-PRESET-3 | S | プリセットをJSONファイルとして書き出し/読み込みできる(バックアップ・共有用)。スキーマは§8参照。 |

## 5. 画面仕様(iPad側)

```
┌─────────────────────────────────────────────────────────┐
│ ツールバー: [コンテンツ選択] [テストパターン] [プリセット] [出力状態●] │
├───────────────────────────────┬─────────────────────────┤
│                               │ インスペクタ(選択中の面) │
│   メッシュ編集キャンバス        │  ・座標数値表示/入力     │
│   (出力プレビュー上に          │  ・微調整十字キー        │
│    12個の●を重ねて表示)        │  ・明るさ/ガンマ         │
│                               │  ・リセット/ロック       │
├───────────────────────────────┴─────────────────────────┤
│ トランスポート: [▶︎/❚❚] [シーク] [ループ] [音量]              │
└─────────────────────────────────────────────────────────┘
```

- **メッシュ編集キャンバス**は出力映像の縮小プレビューを背景に敷き、その上にメッシュとコントロールポイントを重ねる。ユーザーは「投影結果を見ながら」ではなく「実際の壁を見ながら」調整するため、キャンバスは抽象表示(ワイヤーフレーム)モードも選べる。
- 画面は3枚構成: ①エディタ(上図・メイン)、②コンテンツピッカー、③プリセット管理。

## 6. 映像処理パイプライン仕様

```
AVPlayer(H.265 4K, HWデコード)
  └→ AVPlayerItemVideoOutput → CVPixelBuffer(毎フレーム)
       └→ CIImage 化
            ├→ crop(左壁領域)  → CIPerspectiveTransform(左壁4点)  ┐
            ├→ crop(正面領域)  → CIPerspectiveTransform(正面4点)  ├→ 合成(黒背景に3面を配置)
            └→ crop(床領域)    → CIPerspectiveTransform(床4点)    ┘
                 └→ CIContext(Metal-backed) が外部画面の CAMetalLayer へ直接描画
```

- フレーム駆動は**外部ディスプレイ側の `CADisplayLink`**(接続先リフレッシュレートに同期)。
- 全処理をGPU上で完結させ、CPU⇔GPU間のピクセルコピーを発生させない(`CIContext.render(_:to:)` でMetalテクスチャへ直接描画)。
- Core Imageの座標系は左下原点である点に注意(UIKitのUI座標との変換層を設ける)。
- 将来のジャイロ連動・多点ワープに備え、レンダラは「Core Image実装」を差し替え可能なプロトコル(`FrameRenderer`)の一実装として設計する(詳細は `02_技術アーキテクチャ設計.md`)。

## 7. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| N-PERF-1 | 性能 | 4K/30p H.265ソースで出力30fps以上を維持(対象機: A14以降のiPad)。60p対応はA17 Pro/M系を推奨機とする。 |
| N-PERF-2 | 性能 | ポイントドラッグ中もフレーム落ちが体感されないこと(ワープ行列の更新はフレーム単位でアトミックに反映)。 |
| N-THERM-1 | 熱/電源 | 2時間連続投影でサーマルスロットリングによる著しい品質低下がないこと。`ProcessInfo.thermalState` を監視し、`serious` 以上で解像度を段階的に下げて継続する。 |
| N-THERM-2 | 熱/電源 | 給電しながら映像出力できる構成(HDMI+PD給電の複合アダプタ)を推奨環境として明記する。投影中は `isIdleTimerDisabled = true`。 |
| N-COMP-1 | 互換性 | iPadOS 17以降。USB-C搭載iPad(第10世代以降/Air 4以降/Pro 2018以降)を推奨。Lightning機は1080p上限・非推奨と明記。 |
| N-UX-1 | UX | 主要操作はすべて片手タッチで完結。文言は日本語/英語対応。 |
| N-REL-1 | 信頼性 | ケーブル抜断・動画ファイル破損・アプリのバックグラウンド遷移でクラッシュしない。フォアグラウンド復帰時に再生・出力状態を復元する。 |
| N-PRIV-1 | プライバシー | ネットワーク通信なし(v1)。解析SDKを入れる場合はオプトイン。フォトライブラリは限定アクセスAPIを使用。 |

## 9. リスクと対策

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| R1 | **ユーザー自身の影**: 座席がプロジェクター光路の下にあるため、身を乗り出すと床・正面壁に影が落ちる | 没入感の毀損 | 設置ガイド(推奨: 投射光がユーザー頭上を通る高さにプロジェクターを設置)をアプリ内ヘルプに含める。超短焦点機の利用も案内 |
| R2 | **1台で3面カバーする画角の限界**: 通常投射比のプロジェクターでは3面全体を覆えない可能性 | そもそも成立しない部屋がある | 対応可能な部屋サイズ/投射比の早見表をドキュメント化。v1は「コーナー付近のみ覆う」構成も正式サポート(3面すべてが全面を覆う必要はない) |
| R3 | **フォーカス**: 3面で投射距離が異なり、全面で同時にピントが合わない | ボケ | 被写界深度の深い(小開口)機種・レーザー機を推奨。仕様上は解決不能である旨を明記 |
| R4 | 強い台形補正による実効解像度・輝度の低下(特に床) | 画質劣化 | F-WARP-6(面別明るさ補正)。補正量が大きい面への警告表示は将来検討 |
| R5 | 外部ディスプレイAPIの挙動差(機種・iPadOSバージョン) | 出力不能・ミラーリングになる | 実機マトリクスでの early spike(M1マイルストーンの最初に実施)。SwiftUIのみで完結しない場合はUIKitシーン管理で実装 |
| R6 | 4Kデコード+3面ワープの熱 | フレーム落ち・停止 | N-THERM-1の段階的解像度低下。長時間運用向けに1080pソース推奨を案内 |
| R7 | コンテンツ制作の難易度(魚眼動画と3面クロップの対応付け) | 「映したら変」問題 | F-SRC-5のクロップガイドテンプレート書き出し。サンプルコンテンツを同梱 |

## 10. 未決事項(要ユーザー判断)

実装開始前に以下を確定させたい。**暫定値のまま進めても手戻りが小さい順**に並べている。

1. **手持ちのプロジェクターとiPadの機種は?**(投射比・解像度・USB-C/Lightningで推奨構成と性能目標が変わる。特にLightning機なら要件N-COMP-1を再検討)
2. **コンテンツの実解像度・コーデックは?**(AI生成動画が4K/H.265想定で良いか。60pは必要か)
3. **床は本当に「4点補正」で足りるか?** 床への斜め投影は歪みが大きく、部屋によっては4点(平面ホモグラフィ)で合うが、マット・段差があるとグリッドワープ(v2機能)が必要になる。v1は4点で割り切る想定で良いか。
4. **調整スタイルの確認**: 調整中ユーザーは「壁を見ながらiPadを操作」する想定(プレビューは補助)。この前提でUIを設計して良いか。
5. **アプリ名**: 本書では仮に「CornerCast」とした。
6. **配布形態**: 個人利用(Ad Hoc/TestFlight)か、App Store公開を目指すか。(公開するならフォトライブラリ権限文言・審査対応が要件に加わる)
