## 1. 背景と目的

### 1.1 背景
部屋の「左壁・正面壁・床」の3面が交わるコーナーに、プロジェクター1台で斜め上方から映像を投影し、家庭内に「SFコックピット風」の没入空間を作りたい。既存のプロ向けマッピングソフト(MadMapper等のPC製品)は重厚で高価であり、家庭でのカジュアルな用途には過剰。

モバイル向け既存アプリの調査結果(2026-07時点、詳細は `04_技術調査レポート.md` §4): 旧DynaMapperは「Optoma Projection Mapper」に改称後も長期未更新で、静止画中心・矩形マッピングにとどまる。現行の主要iOSマッピングアプリ(SurfaBeam Pro / Lazy Lighting / TouchViZ / ProMapper 等)にも**「部屋のコーナー3面をワンセットで扱う」体験に最適化した製品は存在しない**(HeavyM RemoteはPC必須のリモコン)。「iPad単体完結×動画対応×コーナー3面特化」が本アプリのポジションとなる。MadMapper iOS版の一次確認(App Store)のみ残課題。

### 1.2 目的
- AI生成等で用意した1本の超広角動画を、iPad単体でリアルタイムに「3分割 → 射影変換 → 再合成」し、プロジェクターへ出力する。
- タッチ操作だけで、実際の部屋の角に映像を「カチッと」フィットさせられる直感的なキャリブレーションUIを提供する。
- 重厚なPCソフトなしで、セットアップから投影まで10分以内に完了できる体験を実現する。

### 1.3 ゴール指標(v1)
| 指標 | 目標値 |
|---|---|
| 初回セットアップ〜投影開始 | 10分以内 |
| キャリブレーション操作の反映遅延 | 100ms以内(体感で「リアルタイム」) |
| 投影フレームレート | 30fps以上(60fps目標)、4K/H.265ソース時 |
| 連続投影時間 | 2時間以上(熱・バッテリー条件は§7参照) |

## 2. ユーザーと利用シナリオ

### 2.1 想定ユーザー
- **プライマリ**: 自宅に趣味の没入空間を作りたいガジェット/映像好きの個人。プロジェクターとiPadを所有。映像編集やプログラミングの専門知識は不要とする。
- **セカンダリ**: 小規模イベント・店舗ディスプレイ・子供部屋演出などで簡易マッピングをしたい人。

### 2.2 コアシナリオ(ハッピーパス)
1. プロジェクターを部屋の右後方・天井付近に設置し、コーナー(左壁×正面壁×床)へ斜めに投影する。
2. iPadをUSB-C – HDMIアダプタでプロジェクターに接続する。
3. アプリを起動すると、プロジェクター側に**テストパターン(面ごとに色分けされたグリッド)**が全画面表示される。
4. iPad画面上の3つのメッシュ(左壁/正面壁/床)の4隅ポイント(計12個)をドラッグし、テストパターンの各グリッドが実際の部屋の面にぴったり合うよう調整する。
5. 調整結果を「プリセット」として保存する(次回以降は再調整不要)。
6. 写真ライブラリ/ファイルから超広角動画を読み込むと、動画が3分割・射影変換・合成されてプロジェクターから投影され、部屋のコーナーが立体的な映像空間になる。

### 2.3 ユーザーストーリー(抜粋)
- 「映像の知識がない私でも、ツマミをドラッグするだけで壁の角に映像を合わせたい」
- 「一度合わせた設定は保存して、次回は電源を入れるだけで使いたい」
- 「投影中はプロジェクター側にボタンやUIが一切映ってほしくない」
- 「調整の最後の1〜2pxを指ドラッグでは合わせきれないので、微調整手段が欲しい」

## 3. スコープ定義

### 3.1 スコープ内(v1)
- 動画1本(ローカルファイル)を入力とした3面マッピングと外部ディスプレイ出力
- 静止画の入力(動画の前段階として。テスト・調整用途にも有用)
- 3メッシュ×4点のパースペクティブ補正、クロップ領域調整、プリセット保存
- **2つの出力モード**: ①リアルタイムモード(調整しながら即投影)、②事前レンダリングモード(調整結果を適用した合成済み動画を書き出し、投影時はそれを再生するだけ)

### 3.2 スコープ外(v1では作らない)
- 複数プロジェクター、エッジブレンディング
- ストリーミング入力(NDI/Syphon/AirPlay受信)、カメラ入力
- 4点を超える多点メッシュワープ(ベジェ/グリッドワープ)
- コンテンツ制作機能(動画生成・編集はアプリ外で行う)
- Android / Apple TV / Mac 対応

### 3.3 将来構想(v2以降。設計上は拡張を妨げないこと)
- ジャイロ連動視差(iPadの傾きで視界が動くコックピット演出)
- 面ごとの音響パンニング(左壁→左ch、正面→センター等)
- LiDAR搭載iPad Proによるコーナー自動検出・半自動キャリブレーション
- プレイリスト/シーン切替、外部MIDI/OSC制御

### 4.5 出力モード(リアルタイム / 事前レンダリング)

キャリブレーション(12点の指ドラッグ調整)は両モード共通。違いは「ワープ処理をいつ行うか」だけである。

| ID | 優先度 | 要件 |
|---|---|---|
| F-MODE-1 | M | 出力モードとして「リアルタイム」と「事前レンダリング再生」の2つを提供し、UIで明示的に切り替えられる。 |
| F-BAKE-1 | M | **事前レンダリング(ベイク)**: 現在のプリセット(12点・クロップ・明るさ/ガンマ)を適用した合成済み動画を、アプリ内ストレージへ書き出せる(H.265、音声はそのままコピー)。書き出しはバックグラウンド処理で、進捗表示とキャンセルが可能。 |
| F-BAKE-2 | M | **ベイク再生**: 書き出し済み動画を選ぶと、外部ディスプレイへは`AVPlayer`による全画面再生のみを行う(毎フレームのワープ処理なし)。長時間投影の既定モードとする。 |
| F-BAKE-3 | M | ベイク済み動画は生成時のプリセットと紐付けて管理する。プリセット(12点等)が変更された場合、該当ベイクに「再書き出しが必要」と警告を表示する。 |
| F-BAKE-4 | S | 書き出し前にディスク空き容量を確認し、不足時は見積もりサイズとともに警告する。書き出し解像度(1080p/4K)を選択できる。 |
| F-BAKE-5 | S | ベイク再生中もプリセットの微修正は可能とするが、反映には再書き出しが必要である旨をUIで明示する(再生中のリアルタイム上書きはしない)。 |
| F-RT-1 | M | **リアルタイムモード**: 従来どおり毎フレームワープ処理して出力する。キャリブレーション作業時・コンテンツをすぐ試したい時の既定モード。 |

**モード使い分けの想定フロー**: ①リアルタイムモード+テストパターンで12点を調整 → ②プリセット保存 → ③コンテンツをベイク書き出し → ④普段の投影はベイク再生(低負荷・低発熱)。リアルタイム性能(N-PERF-1)やサーマルスロットリング(N-THERM-1)のリスクは、長時間運用がベイク再生に寄ることで大幅に緩和される。

| F-UI-3 | M | 選択中ポイントの微調整UI(十字キーで±1px、長押しでリピート)。 |

## 5. 画面仕様(iPad側)

```
┌─────────────────────────────────────────────────────────┐
│ ツールバー: [コンテンツ選択] [モード: RT/ベイク] [テストパターン] [プリセット] [出力状態●] │
├───────────────────────────────┬─────────────────────────┤
│                               │ インスペクタ(選択中の面) │
│   メッシュ編集キャンバス        │  ・座標数値表示/入力     │
│   (出力プレビュー上に          │  ・微調整十字キー        │
│    12個の●を重ねて表示)        │  ・明るさ/ガンマ         │
│                               │  ・リセット/ロック       │
├───────────────────────────────┴─────────────────────────┤
│ トランスポート: [▶︎/❚❚] [シーク] [ループ] [音量]              │
└─────────────────────────────────────────────────────────┘
```

- **メッシュ編集キャンバス**は出力映像の縮小プレビューを背景に敷き、その上にメッシュとコントロールポイントを重ねる。ユーザーは「投影結果を見ながら」ではなく「実際の壁を見ながら」調整するため、キャンバスは抽象表示(ワイヤーフレーム)モードも選べる。
- 画面は3枚構成: ①エディタ(上図・メイン)、②コンテンツピッカー、③プリセット管理。

## 6. 映像処理パイプライン仕様

```
AVPlayer(H.265 4K, HWデコード)
  └→ AVPlayerItemVideoOutput → CVPixelBuffer(毎フレーム)
       └→ CIImage 化
            ├→ crop(左壁領域)  → CIPerspectiveTransform(左壁4点)  ┐
            ├→ crop(正面領域)  → CIPerspectiveTransform(正面4点)  ├→ 合成(黒背景に3面を配置)
            └→ crop(床領域)    → CIPerspectiveTransform(床4点)    ┘
                 └→ CIContext(Metal-backed) が外部画面の CAMetalLayer へ直接描画
```

上図は**リアルタイムモード**のパイプライン。**事前レンダリングモード**では同じ「crop×3→warp×3→合成」処理をオフラインの書き出しジョブとして実行し(`AVAssetExportSession`+CIフィルタ適用のビデオコンポジション)、結果をH.265ファイルとして保存する。投影時はそのファイルを`AVPlayer`で全画面再生するだけで、毎フレームのワープ処理は発生しない。

- フレーム駆動は**外部ディスプレイ側の `CADisplayLink`**(接続先リフレッシュレートに同期)。
- 全処理をGPU上で完結させ、CPU⇔GPU間のピクセルコピーを発生させない(`CIContext.render(_:to:)` でMetalテクスチャへ直接描画)。
- Core Imageの座標系は左下原点である点に注意(UIKitのUI座標との変換層を設ける)。
- 将来のジャイロ連動・多点ワープに備え、レンダラは「Core Image実装」を差し替え可能なプロトコル(`FrameRenderer`)の一実装として設計する(詳細は `02_技術アーキテクチャ設計.md`)。

| ID | 分類 | 要件 |
|---|---|---|
| N-PERF-1 | 性能 | **リアルタイムモード時**: 4K/30p H.265ソースで出力30fps以上を維持(対象機: A14以降のiPad)。60p対応はA17 Pro/M系を推奨機とする。ベイク再生モードは単純な動画再生であり本要件の対象外(ソース解像度の再生能力があれば足りる)。 |
| N-PERF-2 | 性能 | ポイントドラッグ中もフレーム落ちが体感されないこと(ワープ行列の更新はフレーム単位でアトミックに反映)。 |
| N-THERM-1 | 熱/電源 | 長時間(2時間以上)の連続投影は**ベイク再生モードを既定**とすることで成立させる(HWデコードのみでGPU負荷が小さい)。リアルタイムモードでの長時間運用に対しては、`ProcessInfo.thermalState` を監視し `serious` 以上でレンダリング解像度を段階的に下げて継続する(実測報告ではM4世代ですら連続GPU高負荷の約9〜17分でスロットリング開始 — 調査レポート§2)。 |
| N-THERM-2 | 熱/電源 | 給電しながら映像出力できる構成を推奨環境として明記する。Thunderbolt/USB-Cポートは給電+DisplayPort出力の同時利用を公式サポート(調査レポート§3)。投影中は `isIdleTimerDisabled = true`。 |
| N-COMP-1 | 互換性 | iPadOS 17以降・USB-C搭載iPad。**4K60出力可**: iPad Pro全機 / Air(M2以降) / Air 5 / mini(A17 Pro) / iPad(A16)。**4K30止まり**: Air 4 / mini 6 / iPad 10(Apple公式仕様)。Lightning機は非対応と明記。推奨アダプタは「HDMI 2.0対応のUSB-C(DP Alt Mode)アダプタ+PDパススルー」— Apple純正Multiportアダプタはアプリ描画が1080pに制限されるため非推奨(リスクR8)。 |
| N-COMP-2 | 互換性 | **macOS対応(Mac Catalyst)**: macOS 14以降のMacでも同一アプリが動作する(v1.2で追加)。外部ディスプレイ用シーンロールはMac Catalyst 16+で公式サポート(調査レポート§1の一次情報)。ただし主ターゲットはiPadであり、Macでの外部ディスプレイ挙動(HDMI出力・シーン生成)は実機検証項目(M1スパイク)に含める。 |
| N-INST-1 | 設置条件 | 対象機材は**通常投射比のプロジェクター**とする(短焦点・超短焦点は使用しない前提。特にUST機は傾け設置不可のため非対応)。設置ガイドに以下を明記する: ①投射角は各面に対し30度以内を目安(超過でフォーカス不均一が発生)、②通常投射比機で3面をカバーするための投射距離(機種の投射比×必要投影幅)の確保、③デジタル台形補正は原理的に実効解像度が低下する旨の注意。 |
| N-UX-1 | UX | 主要操作はすべて片手タッチで完結。文言は日本語/英語対応。 |
| N-REL-1 | 信頼性 | ケーブル抜断・動画ファイル破損・アプリのバックグラウンド遷移でクラッシュしない。フォアグラウンド復帰時に再生・出力状態を復元する。 |
| N-PRIV-1 | プライバシー | ネットワーク通信なし(v1)。解析SDKを入れる場合はオプトイン。フォトライブラリは限定アクセスAPIを使用。 |

## 8. データ仕様(プリセットJSON)

座標はすべて**出力キャンバスに対する正規化座標(0.0–1.0)**で保持し、出力解像度に依存しない。

> **実装ノート(v1.2)**: 正式なスキーマは実装(`MappingPreset`のCodable出力)を正とする。下記の例は概念図であり、実際の出力とは細部が異なる(SwiftのデフォルトCodableにより `crop` は `[[x,y],[w,h]]` の入れ子配列、`loop`/`volume` はトップレベル)。`surfaces` がオブジェクト形状である点は仕様として固定(テストで担保)。人間可読形式へのカスタムCodable化はF-PRESET-3(書き出し機能)を仕上げるM3で判断する。

```json
{
  "schemaVersion": 1,
  "name": "自室コーナー(夜)",
  "updatedAt": "2026-07-18T12:00:00+09:00",
  "surfaces": {
    "leftWall": {
      "crop":  { "x": 0.0, "y": 0.0, "w": 0.33, "h": 0.75 },
      "quad":  { "topLeft": [0.02, 0.05], "topRight": [0.35, 0.10],
                 "bottomRight": [0.35, 0.62], "bottomLeft": [0.02, 0.78] },
      "brightness": 1.0, "gamma": 1.0
    },
    "frontWall": { "crop": {}, "quad": {}, "brightness": 1.0, "gamma": 1.0 },
    "floor":     { "crop": {}, "quad": {}, "brightness": 1.15, "gamma": 0.95 }
  },
  "links": [
    { "a": "leftWall.topRight",    "b": "frontWall.topLeft",   "enabled": true },
    { "a": "leftWall.bottomRight", "b": "frontWall.bottomLeft", "enabled": true },
    { "a": "frontWall.bottomLeft", "b": "floor.topLeft",        "enabled": false },
    { "a": "frontWall.bottomRight","b": "floor.topRight",       "enabled": false }
  ],
  "playback": { "loop": true, "volume": 0.8 }
}
```

## 9. リスクと対策

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| R1 | **ユーザー自身の影**: 座席がプロジェクター光路の下にあるため、身を乗り出すと床・正面壁に影が落ちる | 没入感の毀損 | 設置ガイド(推奨: 投射光がユーザー頭上を通る高さにプロジェクターを設置)をアプリ内ヘルプに含める |
| R2 | **1台で3面カバーする画角の限界**: プロ用イマーシブルームの標準は複数台構成(例: 床+壁2面で6台)であり、1台3面は業界標準外のトレードオフ込み構成。使用する通常投射比機は壁面投影に4〜8m級の投射距離を要するとされ、家庭の部屋では投影範囲が限られる | そもそも成立しない部屋がある/投影が小さくなる | 対応可能な部屋サイズ/投射比の早見表をドキュメント化。v1は「コーナー付近のみ覆う」構成を正式サポート(3面すべてが全面を覆う必要はない) |
| R3 | **フォーカス**: 3面で投射距離が異なり、全面で同時にピントが合わない。投射角30度超でフォーカス不均一が顕著化 | ボケ | 投射角30度以内の設置を案内(N-INST-1)。被写界深度の深い機種・レーザー機を推奨。仕様上は完全解決不能である旨を明記 |
| R4 | 強い台形補正(デジタル補正)は原理的に画素を捨てるため実効解像度・輝度が低下(特に床)。光学レンズシフト非搭載の安価機では回避不能 | 画質劣化 | F-WARP-6(面別明るさ補正)。補正量が大きい面への警告表示は将来検討。レンズシフト搭載機なら劣化なしで斜め投影可能な旨を機材ガイドに記載 |
| R5 | 外部ディスプレイAPIの挙動差(機種・iPadOSバージョン) | 出力不能・ミラーリングになる | 実機マトリクスでの early spike(M1マイルストーンの最初に実施)。SwiftUIのみで完結しない場合はUIKitシーン管理で実装 |
| R6 | 4Kデコード+3面ワープの熱(リアルタイムモード) | フレーム落ち・停止 | **長時間運用はベイク再生モードを既定にする**(F-BAKE-2)ことで根本回避。リアルタイムモードにはN-THERM-1の段階的解像度低下を実装 |
| R7 | コンテンツ制作の難易度(魚眼動画と3面クロップの対応付け) | 「映したら変」問題 | F-SRC-5のクロップガイドテンプレート書き出し。サンプルコンテンツを同梱 |
| R8 | **Apple純正USB-C Digital AV Multiportアダプタはアプリ描画を1080p60に制限**(4K60になるのは動画プレーヤー系コンテンツのMatch Content時のみ、Apple公式仕様)。本アプリの出力は「アプリ描画」なので純正Multiport経由では実質1080pになる可能性が高い | 出力解像度が想定の1/4 | 推奨アダプタを「HDMI 2.0対応のサードパーティ製USB-C(DP Alt Mode)アダプタ+PDパススルー」とし(N-COMP-1)、M1実機スパイクでアダプタ別の実出力解像度を必ず検証する |

## 10. 未決事項(要ユーザー判断)

実装開始前に以下を確定させたい。**暫定値のまま進めても手戻りが小さい順**に並べている。

1. **手持ちのプロジェクターとiPadの機種は?**(投射比・解像度・USB-C/Lightningで推奨構成と性能目標が変わる。特にLightning機なら要件N-COMP-1を再検討)※「短焦点・超短焦点は使わない=通常投射比機」までは確定済み(v1.2)
2. **コンテンツの実解像度・コーデックは?**(AI生成動画が4K/H.265想定で良いか。60pは必要か)
3. **床は本当に「4点補正」で足りるか?** 床への斜め投影は歪みが大きく、部屋によっては4点(平面ホモグラフィ)で合うが、マット・段差があるとグリッドワープ(v2機能)が必要になる。v1は4点で割り切る想定で良いか。
4. **調整スタイルの確認**: 調整中ユーザーは「壁を見ながらiPadを操作」する想定(プレビューは補助)。この前提でUIを設計して良いか。
5. **アプリ名**: 本書では仮に「CornerCast」とした。
6. **配布形態**: 個人利用(Ad Hoc/TestFlight)か、App Store公開を目指すか。(公開するならフォトライブラリ権限文言・審査対応が要件に加わる)
