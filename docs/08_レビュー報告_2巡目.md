## 総評

1巡目は「主経路の外に出ると無言で壊れる」という像を描いた。2巡目はその像を**入口側**へ押し広げる。

確定した11件のうち5件が**永続化の入口の無防備さ**に集まる。`PresetListView.importJSON` は
`PresetStore` が持つ `schemaVersion` ゲートを迂回し、クランプもバリデーションも通さずに

音声セッションの割り込みから復帰しない)で、いずれも**2時間の上映という要件の核心**に当たる。

blocker はゼロ。ただし未検証の指摘に blocker 申告が1件(VoiceOver でのハンドル操作不能)ある。

### 2-1 (medium) インポートしたプリセットが schemaVersion ゲートを素通りする

**場所**: `CornerCast/UI/PresetListView.swift:210-214` / `CornerCast/State/MappingViewModel.swift:16` / `CornerCast/Engine/PresetStore.swift:137-141`

`PresetStore` は「このビルドが知らない `schemaVersion` は読まない」という方針を持ち、`decodePreset` にガードがある。
ところが F-PRESET-3 の読み込み経路 `importJSON` は**ストアを一切通らず**、ローカルの `JSONDecoder` で直接デコードして代入する。

```swift
let preset = try decoder.decode(MappingPreset.self, from: data)   // :213 ゲート無し
viewModel.preset = preset                                          // :214
```

`schemaVersion` に**代入している箇所はリポジトリ全体で0件**(参照は宣言・ガード・テストの3箇所のみ)なので、正規化の機会がない。
`preset` の `didSet` → 500ms 後に `saveLastUsed` が走り、**このビルドが読めない値を、このビルド自身の `lastUsed.json` に焼き付ける**。

**何が起きるか**: 新バージョンで作られたプリセット JSON(`schemaVersion: 2`)を旧バージョンで開く。
成功し、画面にも正しく反映される。500ms 後に `lastUsed.json` へ保存される。再起動すると `loadLastUsed()` が nil を返し、
**その人自身の調整も含めて全部消えて「初回起動のユースケース選択」が出る**。
エラーは最後まで1つも出ない。そこでカードを1枚タップした瞬間に `lastUsed.json` が上書きされ、復旧不能になる。
同じ機構は TestFlight のロールバックや古いビルドの再インストールでも発火する。

**直し方**: `importJSON` を `PresetStore.decodePreset` 経由にしてゲートを共有する。
読めない `schemaVersion` は読み込み自体を拒否し、理由を表示する。
`loadLastUsed()` が nil を返した理由を「無い」と「読めない」で区別し、後者は既定値で上書きせず退避する。

### 2-2 (medium) index.json の1回のデコード失敗で全ベイクレコードが消える

**場所**: `CornerCast/Engine/BakeExporter.swift:245`, `:256-261`, `:264-272` / `CornerCast/UI/TransportView.swift:169`

```swift
let records = (try? decoder.decode([BakeRecord].self, from: data)) ?? []   // :245 失敗を[]に潰す

func add(_ record: BakeRecord) throws {
    var records = list()        // ← 破損時は []
    records.append(record)
    try writeIndex(records)     // ← 全上書き
}
```

`PresetStore` は1プリセット1ファイル + `compactMap` なので破損は1件で止まる。
対して `BakeStore` は**単一配列**で、`JSONDecoder` は配列全体を落とす。**1レコードの不整合が全件を巻き添えにする。**
`BakeRecord` は全8フィールドが非 Optional で版数フィールドも無いため、将来の項目追加でこれが発火しやすい。

`Bakes/` を走査するコードは皆無で、`Info.plist` に `UIFileSharingEnabled` も `LSSupportsOpeningDocumentsInPlace` も無い。
つまり**索引から外れた mp4 は Files.app からも見えず、アプリ削除以外に回収路が無い**。
`export()` は失敗・キャンセル経路で `outputURL` を削除しないので、孤児は実際に発生する。

**直し方**: `list()` の `?? []` をやめ、「空」と「読めない」を区別する。読めないときは書き込みを中止し、
`index.corrupt-<日時>.json` へ退避してから `Bakes/*.mp4` の実走査で再構築する。
`BakeRecord` に `schemaVersion` を足し、追加フィールドは `decodeIfPresent` にする。
`TransportView.swift:169` の `try?` をやめる。

### 2-3 (medium) スリープ抑止の条件が要件とずれている

**場所**: `CornerCast/Scenes/MainSceneDelegate.swift:26-33`

N-THERM-2 (docs/01:222) と docs/02:214 は「**投影中のみ** `isIdleTimerDisabled = true`」と定める。
実装の条件は「**メインUIシーンがアクティブ**」で、`displayState.isConnected` も `outputMode` も参照していない。
コメント自身が「メインシーンのアクティブ状態に連動させる」と、要件と違うことを宣言している。

両方向に誤っている。

- **投影中に抑止が外れる**: Split View / Slide Over / Stage Manager で他アプリにフォーカスが移る、
  コントロールセンターを引き出す、Catalyst で別アプリのウィンドウをクリックする —
  いずれもシーンが inactive になるだけでアプリはフォアグラウンドに留まるのに、`sceneWillResignActive` が無条件に false へ戻す。
- **投影していないのに点きっぱなし**: プロジェクタ未接続で編集しているだけでも `sceneDidBecomeActive` が無条件に true にする。

**何が起きるか**: ベイク再生で90分の映画を投影開始 → Split View でメモアプリを開く → 抑止が外れる →
自動ロック既定2分でロック → アプリがサスペンドされ再生停止 → **上映開始から数分でプロジェクタが最後のフレームで固まる**。
ユーザーには「アプリが落ちた」としか見えない。

**直し方**: 抑止条件を投影の実態から導出する。`externalSceneDidConnect` / `externalSceneDidDisconnect` で
`displayState` を更新する箇所に合わせて `isIdleTimerDisabled = displayState.isConnected` とし、シーン連動を削除する。
あわせて `UIDevice` のバッテリ監視(現状リポジトリ全体で0件)を入れ、docs/01:33 の「連続投影2時間以上」に対して給電を促す。

### 2-4 (low) 読み込んだ数値が一切クランプされない

**場所**: `CornerCast/UI/PresetListView.swift:214` / `CornerCast/Domain/Models.swift:171-179`

値域は ViewModel のミューテータ・OSC の `Self.clamp`・`Slider` の `in:` レンジにしか無く、**Decodable 経路には一切無い**。
`SurfaceConfig.init(from:)` は `decodeIfPresent` で既定値を埋めるだけで値域を見ない。

しかも**表示も修正もできない**。SwiftUI の `Slider(value:in:)` はレンジ外の値をつまみの位置として端に丸めて描くだけで、
ドラッグするまで Binding に書き戻さない。「ガンマ 0.25」と表示されているのに合成へ渡るのは 0 のまま、という状態になる。

- `gamma = 0` → `pow(x, 0) = 1` なので該当面が**全画素最大輝度の白**。壁一面が真っ白になる。
- `feather >= 1.0` → `inset` が短辺の半分以上になり `insetBy` が幅0を返す。**面が完全に消える**。
- `crop` の width/height が 0 や負 → 空/反転矩形で面が消える。

`didSet` で `lastUsed.json` に保存されるので、再起動しても直らない。

**直し方**: `MappingPreset.sanitized()` を用意し、デコードの全経路(`PresetStore.decodePreset` と `importJSON`)を通す。
クランプが効いたら「一部の値を有効範囲へ調整しました」と1行通知する。
あわせて `FrameComposer.feathered` に `amount` の上限ガード(短辺の40%程度で頭打ち)を入れる。

### 2-5 (low) extras / masks の件数に上限が無い

**場所**: `CornerCast/State/MappingViewModel.swift:16`, `:65` / `Models.swift:423-430` / `FrameComposer.swift:21-24`

`RenderParameters.init` は `preset.extras` を全件展開し、`compose` は1件ずつ `composited(over:)` で積む。**上限はどこにも無い。**
UI から増やす経路は1タップ1件だが、デコード経路には何も無い(2-4 と同じ入口)。

読み込むと `lastUsed.json` に保存され、以後**起動のたびに** `init` がそれを読み、
エディタプレビューも外部出力も毎フレーム巨大な CIImage チェーンを組もうとする。
メインアクタ上で返ってこなくなるため UI が固まり、「全てリセット」にも到達できない。
`EditorPreviewRenderer` が未接続時も `compose` を通るので、**プロジェクタ無しでも発火する**。
アンインストール以外の復旧路が存在しない。

**直し方**: 2-4 と同じ入口で件数上限(各64件程度)を設ける。
あわせて「前回起動が正常終了したか」を UserDefaults に持ち、異常終了が続いたら `lastUsed.json` を退避して
既定プリセットで起動するセーフモードを入れる。

### 2-6 (low) 自動保存の失敗が観測できない

**場所**: `CornerCast/Engine/PresetStore.swift:67-71`, `:115-118`

```swift
func saveLastUsed(_ preset: MappingPreset) {
    // 自動保存はプロトコル上throwしない。失敗してもクラッシュさせず握りつぶす(N-REL-1)。
    guard let url = lastUsedFileURL() else { return }
    try? writePreset(preset, to: url)      // :70
}
```

クラッシュさせないことと、失敗を隠すことは別である。`presetsDirectoryURL()` も `try? createDirectory` で失敗を捨て、
**ディレクトリが無いまま URL を返す**。`saveLastUsed` は Void を返すので呼び出し側も検知できない。
ViewModel レベルのエラーチャネルは存在しない(`errorMessage` は各ビューの `@State` のみ)。

`HelpView.swift:46` が「調整結果は自動保存されます」と**ユーザーに明示的に約束している**以上、無言の失敗はその約束と矛盾する。

**何が起きるか**: 4K ベイクを2本作って空きが枯渇する。以後、自動保存は毎回 ENOSPC で失敗するが UI には何も出ない。
30分かけて12点を合わせ直し、翌日開くと前日の状態に戻っている。手がかりがゼロ。

**直し方**: クラッシュしないままでよいが、結果を観測可能にする。`lastAutosaveError` を持たせ、
連続失敗時にエディタ上部へ1行出す。`presetsDirectoryURL()` は作成失敗時に nil を返す。

### 2-7〜2-9 (low) UI 層のライフサイクル

**2-7 `NudgeButton` のリピート Timer** (`InspectorView.swift:372-392`)
停止経路は `onPressingChanged(false)` の1つだけで `.onDisappear` が無い。
押下中にビューが階層から外れると `invalidate` されず、RunLoop が Timer を、Timer がクロージャを、
クロージャが**押下時点の** `action`(= 当時の面/頂点を捕捉)を強参照したまま 10Hz で発火し続ける。
`nudge` は毎回 `pushUndo()` して `updatedAt` を更新するので `scheduleAutosave` が 100ms ごとに再作成され、
**500ms の sleep が永久に完走せず、以後そのセッションでは `lastUsed.json` が二度と保存されない**。
→ `.onDisappear { stopRepeat() }` を付ける。action の焼き付きは、方向ベクトルだけを持たせて発火時に最新の選択を読む形へ。

**2-8 `Timer.publish` を body 内で生成** (`TransportView.swift:77-80`)
body 評価のたびに新しい TimerPublisher が生まれ、`autoconnect` が計測をゼロに巻き戻す。
この body は `viewModel.preset` に依存する(`:55` `:63` `:151`)ため、頂点ドラッグ・スライダ操作・OSC 受信の間はほぼ毎フレーム再評価される。
つまり**そうした操作をしている限り `syncPlaybackUI()` は一度も呼ばれない**。
1巡目 #1(`activeVideoSource` が nil)を完全に直しても、ポーリング方式を残す限り残る別の根。
→ パブリッシャを格納プロパティへ出す。本筋は `addPeriodicTimeObserver` / `timeControlStatus` の購読。

**2-9 キャッシュと tmp が回収されない** (`EditorPreviewRenderer.swift:18-19`, `ContentPickerView.swift:245-267`)
`posterCache: [URL: CIImage]` に上限もエビクションも memory-warning 応答も無い(`NSCache` はリポジトリ全体で0ヒット)。
値は非圧縮ビットマップ(1080p ≒ 8MB、4K ≒ 33MB)。
キーが URL で、PhotosPicker/ファイル読み込みは**毎回 UUID 名の新しい tmp へ原寸コピー**するので、
同じ動画を選び直しても必ずミス → 新エントリになる。`temporaryDirectory` 配下を削除するコードは0件。
→ `NSCache` + memory-warning 応答。tmp は取り込み前に過去分を削除するか Documents 配下で世代管理する
(1巡目 #10 の contentSource 永続化と整合する)。

### 2-10 / 2-11 (low) 長時間運用の前提

**2-10 `AVAudioSession` 未設定** (`VideoSource.swift:36-41`)
`AVAudioSession` / `addObserver` / `UIBackgroundModes` がリポジトリ全体で0ヒット。
カテゴリ未設定の既定は `soloAmbient` で、消音モードで無音・他アプリ音声と排他・ロックで無音になる。
`interruptionNotification` を誰も購読していないため、割り込み後に AVPlayer が pause されたまま放置される。
→ `AppServices.init` で `.playback` を設定し `setActive(true)`。`interruptionNotification` を購読して `.shouldResume` で再開する。

なお申告にあった「割り込みはシーン遷移を伴わないので1巡目 #10 の修正では救えない」は**検証で否定された** —
Siri 起動とフルスクリーン着信は `resignActive` → `becomeActive` を発火させるので、#10 系の修正で主要トリガの多くはカバーされる。

**2-11 解像度の再ネゴシエートを検知しない** (`ExternalDisplayManager.swift:55-60`, `:71-74`)
出力解像度は `externalSceneDidConnect` の**一度だけ** `screen.currentMode?.size` から読まれ、
`canvasSize` / `drawableSize` / `displayState` に焼き込まれる。`paramsProvider` は `resolution` を**値キャプチャ**している。
`UIScreen.modeDidChangeNotification` / `traitCollectionDidChange` はリポジトリ全体で0件。
実運用では「プロジェクタの電源投入直後は1080pで応答し数秒後に4Kへ再ネゴシエート」は普通に起きるが、この間シーンは切断されない。
→ `updateResolution(from:)` を切り出し、接続時とモード変更時の両方から呼ぶ。
アスペクト比が変わったら「合わせ直しが必要です」を出す。

## 反証で消えた指摘(8件)

1巡目と同様、挙がった指摘の相当数が検証で落ちた。参考までに見出しのみ:

- 合成 Decodable のため非Optional フィールドが必須で `schemaVersion` の後方互換が実質機能しない
- 自動保存がバックグラウンド遷移でフラッシュされず、デバウンス中の調整が消える
- 「現在の状態を保存」が必ず新 UUID を振るため既存プリセットを更新できない
- 外部ディスプレイ再接続で `OutputRenderer` が二重生成され CADisplayLink が invalidate されない
- ベイク書き出しの中断で部分ファイルが残り UI から永久に見えない
