## 総評

1巡目は「主経路の外に出ると無言で壊れる」という像を描いた。2巡目はそれを**入口側**へ押し広げる。

A 段階8件のうち3件が**永続化の入口の無防備さ**に集まる。`PresetListView.importJSON` は

### 2-A1 (medium) index.json の1回のデコード失敗で全ベイクレコードが消える

**場所**: `CornerCast/Engine/BakeExporter.swift:245`, `:256-261`, `:264-272` / `CornerCast/UI/TransportView.swift:169`

```swift
let records = (try? decoder.decode([BakeRecord].self, from: data)) ?? []   // :245 失敗を[]に潰す

func add(_ record: BakeRecord) throws {
    var records = list()        // ← 破損時は []
    records.append(record)
    try writeIndex(records)     // ← 全上書き
}
```

`PresetStore` は1プリセット1ファイル + `compactMap` なので破損は1件で止まる。
対して `BakeStore` は**単一配列**で、`JSONDecoder` は配列全体を落とす。**1レコードの不整合が全件を巻き添えにする。**
`BakeRecord` は全8フィールドが非 Optional で版数フィールドも無いため、将来の項目追加でこれが発火しやすい。

`Bakes/` を走査するコードは皆無で、`Info.plist` に `UIFileSharingEnabled` も `LSSupportsOpeningDocumentsInPlace` も無い。
つまり**索引から外れた mp4 は Files.app からも見えず、アプリ削除以外に回収路が無い**。

**直し方**: `list()` の `?? []` をやめ、「空」と「読めない」を区別する。読めないときは書き込みを中止し、
`index.corrupt-<日時>.json` へ退避してから `Bakes/*.mp4` の実走査で再構築する。
`BakeRecord` に `schemaVersion` を足し、追加フィールドは `decodeIfPresent` にする。`TransportView.swift:169` の `try?` をやめる。

### 2-A2 (medium) NudgeButton のリピート Timer が生き残る

**場所**: `CornerCast/UI/InspectorView.swift:372-392`

停止経路は `onPressingChanged(false)` の1つだけで `.onDisappear` が無い。
押下中にビューが階層から外れると `invalidate` されず、RunLoop が Timer を、Timer がクロージャを、
クロージャが**押下時点の** `action`(= 当時の面/頂点を捕捉)を強参照したまま 10Hz で発火し続ける。

被害は座標だけに留まらない。`nudge` は毎回 `pushUndo()` して `updatedAt` を更新するので
`scheduleAutosave` が 100ms ごとに前回タスクをキャンセルして作り直し、**500ms の sleep が永久に完走しない**。
以後そのセッションでは `lastUsed.json` が二度と保存されない。

**起きること**: 十字キーを長押ししたまま別の頂点をタップすると、選択していない面の頂点が勝手に滑っていく。
長押し中に `selectedCorner` が nil になる経路(面を追加、テンプレート適用)が走ると
`NudgeButton` ごと階層から消えて停止コールバックが届かず、**指を離しても頂点が 10Hz で動き続ける**。

**直し方**: `.onDisappear { stopRepeat() }` を付ける。action の焼き付きは、方向ベクトルだけを Timer に持たせて
発火時に最新の viewModel/選択を読む形へ変える。リピート中の `pushUndo` は開始時の1回だけに絞る。

### 2-A3 / 2-A4 / 2-A5 (low) 永続化の入口が無防備 — 根は1つ

`importJSON` はストアを一切通さず、ローカルの `JSONDecoder` で直接デコードして代入する。

```swift
let preset = try decoder.decode(MappingPreset.self, from: data)   // :213 ゲート無し
viewModel.preset = preset                                          // :214
```

ここから3つの症状が出る。

**2-A3 `schemaVersion` ゲートの迂回** — `schemaVersion` に代入している箇所はリポジトリ全体で0件なので正規化の機会がない。
新バージョンで作られたプリセット(`schemaVersion: 2`)を旧バージョンで開くと成功してしまい、
500ms 後に `lastUsed.json` へ焼き付く。再起動すると `loadLastUsed()` が nil を返し、
**その人自身の調整も含めて全部消えて「初回起動のユースケース選択」が出る**。エラーは1つも出ない。
そこでカードを1枚タップした瞬間に上書きされ、復旧不能になる。

**2-A4 値域のクランプが無い** — 値域は ViewModel のミューテータ・OSC の `clamp`・`Slider` の `in:` にしか無く、Decodable 経路には無い。
しかも `Slider(value:in:)` はレンジ外の値をつまみ位置として端に丸めて描くだけで、ドラッグするまで書き戻さない。
「ガンマ 0.25」と表示されているのに合成へ渡るのは 0 のまま、という状態になる。
`gamma = 0` は `pow(x,0)=1` で**面が全画素最大輝度の白**、`feather >= 1.0` は `insetBy` が幅0を返して**面が消える**。

**2-A5 件数の上限が無い** — `RenderParameters.init` は `extras` を全件展開し、`compose` は1件ずつ積む。上限はどこにも無い。
巨大な配列を読み込むと `lastUsed.json` に保存され、**起動のたびに** UI が固まって「全てリセット」にも到達できない。
`EditorPreviewRenderer` が未接続時も `compose` を通るので**プロジェクタ無しでも発火する**。

**直し方(3件まとめて)**: `MappingPreset.sanitized()` を用意し、
`schemaVersion` チェック・値域クランプ・件数上限(各64件程度)をそこに集約する。
**デコードの全経路(`PresetStore.decodePreset` と `importJSON`)を必ず通す。**
クランプが効いたら「一部の値を有効範囲へ調整しました」と1行通知する。
あわせて「前回起動が正常終了したか」を UserDefaults に持ち、異常終了が続いたら `lastUsed.json` を退避するセーフモードを入れる。

### 2-A6 (low) スリープ抑止の条件が要件とずれている

**場所**: `CornerCast/Scenes/MainSceneDelegate.swift:26-33`

N-THERM-2 (docs/01:222) は「**投影中のみ** `isIdleTimerDisabled = true`」と定めるが、実装の条件は「**メインUIシーンがアクティブ**」。
`displayState.isConnected` も `outputMode` も参照していない。コメント自身が要件と違うことを宣言している。

両方向に誤っている。投影中でも Split View / Slide Over / コントロールセンター / Catalyst の別ウィンドウで
シーンが inactive になると抑止が外れる(アプリはフォアグラウンドのまま、投影は続いている)。
逆にプロジェクタ未接続で編集しているだけでも点きっぱなしになる。

**起きること**: ベイク再生で90分の映画を投影 → Split View でメモアプリを開く → 抑止が外れる →
自動ロック既定2分でロック → **上映開始から数分でプロジェクタが最後のフレームで固まる**。

**直し方**: `isIdleTimerDisabled = displayState.isConnected` を接続/切断のハンドラで設定し、シーン連動を削除する。
数行で、上映が数分で止まる事故を防げる。

### 2-A7 / 2-A8 (low) UI 層のライフサイクル

**2-A7 `Timer.publish` を body 内で生成** (`TransportView.swift:77-80`)
body 評価のたびに新しい TimerPublisher が生まれ、`autoconnect` が計測をゼロに巻き戻す。
この body は `viewModel.preset` に依存する(`:55` `:63` `:151`)ため、頂点ドラッグ・スライダ操作・OSC 受信の間はほぼ毎フレーム再評価される。
つまり**そうした操作をしている限り `syncPlaybackUI()` は一度も呼ばれない**。
1巡目 #1(`activeVideoSource` が nil)を完全に直しても、ポーリング方式を残す限り残る別の根。
→ パブリッシャを格納プロパティへ出す。本筋は `addPeriodicTimeObserver` / `timeControlStatus` の購読。

**2-A8 キャッシュと tmp が回収されない** (`EditorPreviewRenderer.swift:18-19`, `ContentPickerView.swift:245-267`)
`posterCache: [URL: CIImage]` に上限もエビクションも memory-warning 応答も無い(`NSCache` は0ヒット)。
値は非圧縮ビットマップ(1080p ≒ 8MB、4K ≒ 33MB)。
キーが URL で、PhotosPicker/ファイル読み込みは**毎回 UUID 名の新しい tmp へ原寸コピー**するので、
同じ動画を選び直しても必ずミス → 新エントリになる。`temporaryDirectory` 配下を削除するコードは0件。
→ `NSCache` + memory-warning 応答。tmp は取り込み前に過去分を削除するか Documents 配下で世代管理する。

## B. 判定割れ(6件) — 人が判断すること

**事実関係はどれも両方の判定で「本物」と確認されている。**割れているのは「欠陥と呼ぶか」の評価。

### B1 ベイク書き出しの中断で部分ファイルが残る (`BakeExporter.swift:106`)

`export` の `defer` は `progressPoller.cancel()` と `currentExport = nil` のみで、
3つの `resume(throwing:)` 経路のいずれにも出力ファイルの削除が無い。`bakeStore.add` は成功パスのみ。
`Documents/Bakes/<UUID>.mp4` に書き途中の実体が残り、`index.json` に載らないので UI から見えず削除できない。

- **1回目「反証」** — 中断は例外的で、実害の到達に前提が多い。
- **2回目「確定・medium」** — 引用は全て一致、`removeItem` は削除機能の1箇所のみで後始末は存在しない。数回繰り返せば
  F-BAKE-4 の空き容量チェックが自分の残骸を理由に書き出しを拒否し始める。

**判断材料**: 「中断がどれくらい起きるか」の見積もりが割れている。実機で書き出し中にホームへ抜けて確認すれば即決着する。
直すこと自体は `defer` に1行足すだけなので、**議論するより直す方が安い。**

### B2 TransportView が body 評価のたびに index.json を同期読みする (`TransportView.swift:150`)

`isStaleBakeExists` が `bakeStore.list()` を呼び、これがファイル読み+JSON デコードを行う。
body は `viewModel.preset` に依存するため、ドラッグ中はほぼ毎フレーム評価される。

- **1回目「反証」** — ファイルは小さくキャッシュに乗るので実測上の影響は無視できる。
- **2回目「確定・low」** — 投影の CADisplayLink と同じメインランループなので、原理的には競合する。

**判断材料**: これは**実測でしか決まらない**。ベイクを数十本作った状態でドラッグして fps を見るべき。
2-A7 を直す際に `isStaleBakeExists` をキャッシュ化すれば付随的に消える。

### B3 saveLastUsed が書き込み失敗を握り潰す (`PresetStore.swift:70`)

`try? writePreset(...)` で例外を捨て、`saveLastUsed` は Void を返すので呼び出し側も検知できない。
ViewModel レベルのエラーチャネルは存在しない。`HelpView.swift:46` は「調整結果は自動保存されます」と約束している。

- **1回目「確定・low」** — 無言の失敗はその約束と矛盾する。
- **2回目「反証」** — 申告の「**永久に**無効化される」が誤り。`presetsDirectoryURL()` は毎回呼ばれ
  `createDirectory` を毎回再試行するので、空き容量が回復すれば自動的に直る。恒久性を前提にした深刻度は成立しない。

**判断材料**: 2回目の指摘が正しい(恒久的ではない)。ただし「失敗が見えない」こと自体は両方が認めている。
**「永久に壊れる」ではなく「一時的な失敗が見えない」問題として、low で扱うのが妥当。**

### B4 「現在の状態を保存」が必ず新 UUID を振る (`PresetListView.swift:150`)

`saveCurrent()` は無条件に `p.id = UUID()`。上書き経路が存在しない。名前欄には既存名がプリフィルされる。

- **1回目「反証」** / **2回目「確定・low」**(申告の medium からは格下げ)

**起きること**: 本番前日に「本番用」を保存 → 当日微調整して再度保存 → 「本番用」が2行に増える。
どちらが当日版か時刻でしか分からない。片方をフルスワイプで削除すると(1巡目 #7 のとおり確認なしで)当日版が消えうる。

**判断材料**: 1巡目 #7(フルスワイプ削除に確認が無い)と組み合わさると実害が跳ね上がる。**#7 とセットで判断すべき。**

### B5 AVAudioSession 未設定 (`VideoSource.swift:39`)

`AVAudioSession` / `addObserver` / `UIBackgroundModes` はリポジトリ全体で0ヒット。既定は `soloAmbient`。

- **1回目「確定・low」** / **2回目「反証」** — 1巡目 #10 が既に「`AVAudioSession` / `NotificationCenter` が0件」と
  逐語で記載しており**実質的な既出**。また Siri 起動とフルスクリーン着信は `resignActive` → `becomeActive` を発火させるので、
  #10 系の修正で主要トリガの多くはカバーされる。

**判断材料**: 2回目が正しい。**1巡目 #10 の一部として扱い、独立項目にはしない。**
ただし消音スイッチで音が出ない件は #10 に含まれないので、そこだけ別途拾うこと。

### B6 外部ディスプレイの解像度変更を検知しない (`ExternalDisplayManager.swift:56`)

解像度は接続時に一度だけ読まれ、`paramsProvider` は値キャプチャしている。`UIScreen.modeDidChangeNotification` は0件。

- **1回目「確定・low」** / **2回目「反証」** — 申告の中核「アスペクト比が変わると12点で合わせた面の形が崩れる」が**数学的に誤り**。
  合成は正規化座標 → 軸別異方スケールなので、「古い canvasSize で描いてレイヤが引き伸ばす」写像と
  「実パネル解像度で直接描く」写像は同一。numpy で再実装して確認済み。

**判断材料**: 2回目が正しく、**形は崩れない**。残るのは (a) 4K パネルに 1080p を引き伸ばすので**解像度が出ない**、
(b) ツールバーの解像度表示が嘘になる、の2点。実害はあるが申告よりずっと軽い。

### 2-C1 (medium) テストが何も守っていない

`FrameComposerTests.swift:24,32,43,55,88` と `ProFeatureTests.swift:131,143,154,170` の**9箇所すべて**が、
アサーションは `XCTAssertEqual(result.extent, CGRect(origin: .zero, size: canvas))` のみ。

`compose` は `CIImage(color:.black).cropped(to: canvasRect)` を基底に置き、以降は `composited(over:)` しかしない。
source-over の extent は基底を含むので、**この等式は合成の中身に関わらず恒真**。

**起きること**: 描画順を反転させる、色補正ブロックを丸ごと落とす、`ciRect` の Y 反転を取り違える —
いずれもユニットテスト9件はグリーンのまま、CI も緑のまま、実投影を見るまで誰も気づかない。

**直し方**: `CIContext(options: [.useSoftwareRenderer: true])` で小さいキャンバス(64×36)に render して画素を読む。
(a) 各面 quad の中心画素がソース色で面の外が黒、(b) 床と正面壁を重ねたとき重複領域が正面壁の色(F-WARP-3 の描画順)、
(c) `brightness=0.5` で画素値がおよそ半分、(d) マスク quad の内側が黒。CI ランナーは GPU 無しでもソフトウェアレンダラで動く。

### 2-C2 (medium) NaN が clamp を素通しする

`ControlHub.swift:220-222` の `clamp` と `Models.swift:68-70` の `Quad.clamped` は Swift の総称 `min`/`max` を使う。
`max(x,y) = y>=x ? y : x` / `min(x,y) = y<x ? y : x` なので、**`x = NaN` では両方の比較が false になり NaN が素通しする**
(`FloatingPoint` 用の NaN 対応オーバーロードは stdlib に存在しない)。Python で同じ述語を再実装して実測: `clamp(NaN,0,1) → NaN`。

NaN が `preset` に入ると `JSONEncoder.encode` が throw し、`saveLastUsed` は `try?` で捨てる(2-B3)。
つまり**以後の自動保存が無言で失敗し続ける**。ユーザーが手で12点を合わせ直しても保存されない。

**直し方**: `clamp` / `Quad.clamped` を `v.isFinite ? min(max(v, lo), hi) : lo` に変える。
`apply(osc:)` の冒頭に `guard floats.allSatisfy(\.isFinite) else { return }` を置く。
